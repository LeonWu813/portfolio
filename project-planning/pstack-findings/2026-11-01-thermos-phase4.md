## Findings, deduplicated, highest first

### Bugs / security (thermo-nuclear-review)

- **B-L1 Low: return-path check bypassable with tab/newline (defence in depth).** `site/app/slideshow/useFullscreenSession.ts:19-27`, used at `:96-98`. `isReturnPath` checks the raw string (starts with `/`, not `//`, no `\`, not `/slideshow`), but the URL parser strips tabs/newlines: `new URL("/\t/evil.com", "https://www.leon-wu.com/x").href` is `https://evil.com/` (verified in node); Next's router treats a different origin as external (`app-router-instance.js:271`) and does a full load. Not exploitable today: the only source is same-origin, same-tab `sessionStorage["slideshow-return"]` under 10 s old. Also `/slideshow/` and `/slideshow?x` pass the check (leaving would re-enter the slideshow). Fix: `const u = new URL(path, location.origin); if (u.origin !== location.origin || u.pathname === "/slideshow") { direct visit }`, route to `u.pathname`.
- **B-L2 Low: leaving leaves a duplicate history entry.** `useFullscreenSession.ts:98` with `Sidebar.tsx:104`. Stack `[A]` → push → `[A, /slideshow]` → `router.replace(A)` → `[A, A]`; the next Back appears to do nothing. Follows CONV-006 (prd.md:953 requires `router.replace`). Fix if wanted: `router.back()` when opened from the site, `replace("/")` for direct visits; needs a CONV-006 change.
- **B-L3 Low: on touch-screen laptops a stale mouse entry can swallow later taps/swipes.** `site/app/slideshow/useSlideInput.ts:144-159`. Entries are removed only on `pointerup`/`pointercancel` on the layer; a mouse release outside the window or a right-click context menu (macOS Chrome often loses `pointerup`) leaves `pointerId` 1 in the map, and line 146 then marks every later touch as multi-touch until the next left click. Fix: count only non-mouse entries for the multi-touch test, or clear on `lostpointercapture`/`blur`/`contextmenu`.
- **B-L4 Low (a11y): the overlay's close control reads as the picture.** `site/app/projects/[slug]/ImageZoom.tsx:128-140`. `showModal()` focuses the full-screen inner `<button>` whose only name is the copied `<img alt>`, so a screen reader hears "Screenshot of …, button". Fix: `aria-label="Close image"` on the inner button and `alt=""` on the copy (the dialog already has `aria-label={alt}`).
- **B-I1 Info:** the overlay ignores resize/rotate while open (copy off-centre, close animates to the old spot). Cosmetic.
- **B-I2 Info:** `/og-image.png` does not exist in `public/`; `slideshow/page.tsx:19,28` copies the existing site-wide reference. Known open item (no `metadataBase` either, so og:image resolves to localhost in local builds).
- Checked and fine: no `dangerouslySetInnerHTML`; `?project=` only maps to four fixed keys (`parseProjectKey`, deck.ts:475); all image/link sources are constants; ImageZoom's `pushState` works with Next 16's patched history (`app-router.js:252-262`), popstate listener removes itself; full-screen session fix from 22eadb2 holds (`wasFullscreenRef`, `leavingRef`, StrictMode-safe exit timer, entry read once); no listener leaks in useFullscreenSession, useSlideInput, Sidebar; hydration fine (`Slideshow` under `<Suspense>`, ThemeToggle `useSyncExternalStore` with server snapshot false, Sidebar returns null on `/slideshow` server-side too); modifier/non-left clicks open `/slideshow` in a new tab without full screen; holding `7` does not stack history; the `Subject.png` move renders as before and is absent on `/slideshow`; the experience sort removal is intended (AC-118/119); no new env vars, scripts or config.

### Maintainability (thermo-nuclear-code-quality-review)

- **Q-H1 High: `SlideId = string`, so the deck's internal links are unchecked.** `site/app/slideshow/deck.ts:3`, `:87`, `navigation.ts:28-31`. Ids are hand-written in five places (`PROJECTS[].slideIds` deck.ts:62-80, `SLIDES` keys, `TimelineEntry.opens.slideId` deck.ts:110/116, `ABOUT_ORDER`/`JOB_SLIDES`/`GOFREIGHT_KEY_SLIDE`/`EXASCEND_KEY_SLIDE`, literals `"1"`/`"2"`/`"M"` in navigation.ts and Slideshow.tsx:73); a typo compiles and `SLIDES[current]` is undefined at runtime. Fix: `const SLIDES = {…} as const satisfies Record<string, Slide>` and `type SlideId = keyof typeof SLIDES`; bigger version: each project owns its `slides` and the map is derived.
- **Q-H2 High: navigation duplicates the timeline's data.** `navigation.ts:29-31, 90-101`: `digit()` on slide "2" hand-copies `SLIDES["2"].entries[].opens` (key 1 → "2b", key 2 → "2a", running backwards against visual order); `opens.key` is a string while `digit` is a number. Fix: dispatch on slide kind (job → back to parent timeline; timeline → find entry by `opens.key`; menu → index `PROJECTS`), deleting `JOB_SLIDES`, both `*_KEY_SLIDE` constants and the literals; keep named `HOME` and `MENU`.
- **Q-H3 High: the Sidebar/slideshow handoff contract is duplicated.** `site/components/Sidebar.tsx:89-105` and `useFullscreenSession.ts:6-50, 60-63`: storage key literal vs `RETURN_KEY`; payload `{path, t, fs}` written ad hoc and read back through a cast; `"/slideshow"` three times; the full-screen request coded twice with different guards; writer `fs` vs reader `fullscreenRequested`. Fix: a neutral `site/lib/slideshow-handoff.ts` (`SLIDESHOW_PATH`, `writeSlideshowEntry`, `readSlideshowEntry`, `requestFullscreen`). Ownership of `site/lib/` is a Tech Lead / PM decision (it is unowned today; earlier the Tech Lead rejected a shared `site/lib/fullscreen.ts` for that reason).
- **Q-H4 High: the shared shell checks for one feature's route.** `Sidebar.tsx:214-234`, `app/layout.tsx:40-48`: `usePathname()`/`onSlideshow`, an early `return null`, and the `Subject.png` decoration moved into Sidebar so it disappears with it; the root layout still renders the spacer, `md:ml-64` wrapper and scrolling `<main>` under the slideshow, which a fixed z-40 layer covers. Fix: `app/(site)/layout.tsx` for the site pages, `app/slideshow/` outside. Note: this is the route-group option the Tech Lead weighed and rejected in the rev 1.7 + 1.8 review (T1 (b), Leon chose the recommendation) because it rewrites the Source Paths of MOD-001 to MOD-010.
- **Q-M1 Medium: two mechanisms block digits while the zoom is open.** Sidebar's `dialog[open]` check (`Sidebar.tsx:220`) and ImageZoom's `stopPropagation` on `/^[1-7]$/` (`ImageZoom.tsx:123-125`, hard-coding Sidebar's shortcut count). Fix: keep only the Sidebar guard. (The ImageZoom guard was added before MOD-001 landed; QA verified AC-129 with both.)
- **Q-M2 Medium: menu-hint lifecycle spread across reducer, timers and CSS.** `navigation.ts:3-8, 23-24, 117-120`, `Slideshow.tsx:93-104`, `MenuHint.tsx`: three phases, two extra actions, two JS timers mirroring CSS durations (`MENU_HINT_EXIT_MS = 150` duplicates `--ss-dur-moderate`). Fix: CSS owns timing, dispatch `hint-gone` on `onAnimationEnd`; `hint` becomes `{ nonce } | null`.
- **Q-M3 Medium: `useFullscreenSession` mixes three concerns.** `useFullscreenSession.ts:73-160`: a redundant second `fullscreenchange` listener (`:138-140`) since `fullscreenHintVisible` is already gated on `!isFullscreen` (`:155`); `hintArmed` + `hintDismissed` should be one state; `entryRef.current ??= readEntry()` duplicated at `:95` and `:119` with a side-effecting reader; the `mountedRef` + `setTimeout(0)` StrictMode workaround (`:106-116`) is uncommented. Fix: split `useFullscreenHint(isFullscreen)`, one `getEntry()` helper, comment the workaround.
- **Q-M4 Medium: announcements and timers scattered in `Slideshow.tsx`** (`:21-25, 79-113`): the live region is written by three effects with three delay constants. Fix: a `useAnnouncer()` hook.
- **Q-M5 Medium: gesture classification buried in `onPointerUp`** (`useSlideInput.ts:161-198`); `gesture.startedOnButton || isInsideButton(event.target)` repeated (`:174`, `:192`). Fix: a pure `classifyGesture(gesture, end)`.
- **Q-M6 Medium: duplicated logic in the slideshow.** Project position computed twice (`Slideshow.tsx:27-33`, `SlideView.tsx:66-83`) → `slidePosition()` in deck.ts; the title block copied three times (`SlideView.tsx:18-27`, `:90-93`, `Menu.tsx:17-20`) and the `content` + `TitleBlock` wrapper repeated in ten cases.
