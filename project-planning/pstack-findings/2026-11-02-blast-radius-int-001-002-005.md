## INT-001: `metadataBase: new URL("https://www.leon-wu.com")` in `site/app/layout.tsx`

**What it does.** Next resolves relative metadata URLs against `metadataBase`. Absolute URLs are left alone: `resolveUrl` in `site/node_modules/next/dist/lib/metadata/resolvers/resolve-url.js:70-84` returns early when `new URL(url)` parses (lines 74-75), and only otherwise joins with `metadataBase` (line 84). Without `metadataBase` it falls back to `createLocalMetadataBase()` = `http://localhost:${PORT||3000}` (lines 48, 78-79), which is today's localhost og:image.

**Consumers.** Every page file's only relative metadata URL is `/og-image.png` (openGraph.images and twitter.images): `app/page.tsx:15,25`, `about/page.tsx:13,23`, `contact/page.tsx:12,21`, `experience/page.tsx:13,20`, `skills/page.tsx:14,24`, `projects/[slug]/page.tsx:54,60`, `slideshow/page.tsx:19,28`. Every `url:` and `alternates.canonical` is already absolute `https://www.leon-wu.com/...`.

**The one safety fact: absolute URLs do not change, only `/og-image.png` does.** Step 4 (ran it, same URL resolution Next uses):
```
/og-image.png -> https://www.leon-wu.com/og-image.png
https://www.leon-wu.com/experience -> https://www.leon-wu.com/experience
https://www.leon-wu.com/projects/siteplus -> https://www.leon-wu.com/projects/siteplus
```
So no canonical or og:url doubles up or breaks.

**Risks.**
- og:image now points at `https://www.leon-wu.com/og-image.png`, which 404s until Leon says "use the OG image" (INT-001 part 2 not approved). Expected per the decision; link previews show no image either way.
- Vercel preview deployments: `getSocialImageMetadataBaseFallback` (resolve-url.js:58-66) uses the preview URL for social images when `VERCEL_ENV === 'preview'` in production builds, otherwise `metadataBase`. No action needed; noted so QA is not surprised by preview og:image URLs.
- Local QA builds will now show `https://www.leon-wu.com/og-image.png` instead of localhost, and the Next build warning about a missing metadataBase should disappear.

**Cleared.** No page sets its own `metadataBase`; no page uses a relative canonical.

**Before you merge.** Build, then `grep -o 'og:image" content="[^"]*' .next/server/app/*.html` shows `https://www.leon-wu.com/og-image.png` on every route, and canonicals are unchanged.
