### FAIL
- **FAIL AC-095 (intermittent, reproducible): the slideshow bounces itself out of full screen to Home right after a successful opening from the site.**
  - Repro: build + start; headless Chrome on `/about`; install nothing special; send a trusted CDP `Input.dispatchKeyEvent` key "7" (`Digit7`), wait 4 s. Observed: 4 of 16 runs in one batch (and 2 of 3, 1 of 3, 1 of 10 in earlier batches) ended on path `/` with `document.fullscreenElement` null although `fullscreenchange` had fired with full screen on. Expected per AC-095 and CONV-006: stays on `/slideshow` in full screen showing slide 1; (when it later leaves) it returns to `/about`. The same runs without the instrumentation passed 30 of 30, so it is a timing race, more likely when the page is a little slower.
  - Trace of a failing run (ms since the key): keydown 4, `pushState('/slideshow')` 27, `document.exitFullscreen()` called by the slideshow chunk 33, `getItem("slideshow-return")` returns `{"path":"/about","t":...,"fs":true}`, `history.replaceState('/')` (Next router.replace("/")) 32-37, `fullscreenchange(true)` 37, exit, `fullscreenchange(false)` 81.
  - Cause (read from `site/app/slideshow/useFullscreenSession.ts`): `subscribe` (line 83) sets `wasFullscreenRef.current = true` as soon as `document.fullscreenElement` is set, but the `useSyncExternalStore` snapshot rendered during hydration was still `false`. The effect at lines 102-103 then runs with `isFullscreen === false` and `wasFullscreenRef === true`, reads that as an "in" to "out" change and calls `leave()`. `leave()` runs before the entry-read effect (line 119) has filled `entryRef`, so its target is `"/"` and not the opening page, and it calls `exitFullscreen()`. The spec says only a change from "in" to "out" counts as leaving; here full screen had never been seen "in" by the component. This happens when full screen turns on between the first render and the mount effects, which is exactly the window a real full-screen request opens.
  - Consequence for Leon: Cmd/click on Slideshow or `7` sometimes flashes the slideshow and lands on Home, not in full screen. On his Mac, with the macOS full-screen animation, the timing is unknown; it can not be ruled out from headless.
  - Classification: implementation bug. First failure of AC-095 (no earlier QA Results, no escalation marker). Route: Engineer.
